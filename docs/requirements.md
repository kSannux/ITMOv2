# Требования (practice_04)

Цель: настроить агентскую среду и продемонстрировать её применение с использованием выбранного skill и собственного MCP, включая автоматическую проверку результатов.

1. Область и контекст
- Агент работает в контексте репозитория и читает правила из AGENTS.md.
- Среда настраивается в рамках текущего проекта; допускается добавление новых файлов (без изменения существующих без явного разрешения).
- Проверка запускается одной командой: sh scripts/check.sh (runner).

2. Выбранные подключения и обоснование
- Skill: markdown-review
  - Задача: повысить качество документации, автоматически проверяя Markdown-файлы.
  - Проверки: битые локальные ссылки, незакрытые блоки кода, недостающие разделы.
  - Польза: предотвращает поломки навигации и форматирования, снижает техдолг.
- MCP: search_course_materials
  - Задача: находить информацию в материалах курса (lections/, practices/, docs/, README.md).
  - Возвращает: совпадения с путями и фрагментами текста, помогает быстро уточнять контекст.

3. Поведение агента и среда
- Агент должен:
  - Прочитать AGENTS.md и следовать указаниям по контракту и runner.
  - Загрузить skill markdown-review и выполнить проверки по указанным путям.
  - По необходимости вызывать MCP search_course_materials для уточнения контекста (например, поиск упоминаний разделов/примеров).
  - После внесения правок инициировать автоматическую проверку (sh scripts/check.sh) и обработать её результат.

4. Skill markdown-review — интерфейс и требования
- Вход:
  - target_paths: строка-глоб (например, "docs/**/*.md") или список путей/глобов (обязательное поле).
  - required_sections: список строк с названиями разделов, которые должны присутствовать (например, ["Introduction", "Usage"]).
  - options (необязательные):
    - check_anchors: true/false — при true дополнительно проверять якоря в пределах файла (по умолчанию false).
- Проверки:
  - Битые локальные ссылки: относительные ссылки [text](relative/path.md) на отсутствующие файлы (внешние http-ссылки не проверяются).
  - Незакрытые блоки кода: несбалансированное количество ``` (учёт вложенности не требуется).
  - Недостающие разделы: отсутствие заголовков вида ^#{1,6} +<section> для каждого из required_sections.
- Выход:
  - issues: список объектов { type: "broken_link" | "unclosed_code_block" | "missing_section", file, line?, message }.
  - summary: агрегированные счётчики по типам.
- Успех: issues пустой список.
- Ошибочный вход: отсутствует target_paths → ошибка INVALID_INPUT с понятным описанием.

5. MCP search_course_materials — интерфейс и требования
- Tool: search_course_materials.search
- Источники по умолчанию: lections/**, practices/**, docs/** (если папка существует), README.md в корне.
- Вход:
  - query: строка (обязательная, длиной ≥ 2 символов).
  - include: строка-глоб или список глобов (например, "practices/practice_04/**") — необязательный фильтр.
  - limit: число результатов (по умолчанию 10, максимум 100).
- Выход:
  - results: список объектов { path, line, snippet }.
  - meta: { query, count, truncated: true/false }.
- Ошибки:
  - Пустой/слишком короткий query → INVALID_INPUT.
  - Недопустимый include-глоб → INVALID_INCLUDE.
  - Отсутствие результатов — не ошибка (results пустой, count = 0).

6. Автоматическая проверка
- Единая команда: sh scripts/check.sh.
- Скрипт запускает тесты (например, pytest) и возвращает корректный код выхода.
- Тесты покрывают:
  - Skill markdown-review:
    - Корректный вход (существующие .md) → валидный отчёт (issues по существу или пустой список).
    - Ошибочный вход (нет target_paths) → ошибка INVALID_INPUT.
  - MCP search_course_materials:
    - Успех: query на реальную строку в материалах курса возвращает results с корректными path и snippet.
    - Ошибка: query < 2 символов → INVALID_INPUT; некорректный include → INVALID_INCLUDE.
- Вывод проверки должен быть пригоден для чтения агентом/разработчиком.

7. Критерии приёмки
- Среда агента настроена и продемонстрировано её применение:
  - Чтение AGENTS.md, загрузка skill, вызов MCP tool.
  - Автоматическая проверка после правок и возврат результата.
- Skill:
  - Содержательная автоматизация (описание + запуск + результат) либо разбор готового skill (3–4 предложения) с подтверждением запуска.
- MCP:
  - Полезный tool, демонстрация успешного и ошибочного вызовов с обработкой ошибок.
- Рефлексия: файл reflection.md с конкретными наблюдениями.

8. Ограничения и договорённости
- Не изменять контракт и runner без явного разрешения (см. AGENTS.md).
- Новые файлы допускаются (skill, MCP, тесты, скрипты, документация).
- Подтверждения должны быть воспроизводимыми (команды, вывод, ссылки на файлы).

9. Поставляемые артефакты
- Файлы настроенной среды: AGENTS.md, skill (practices/practice04/skill/markdown-review/SKILL.md. и DEMO), MCP-конфигурация/реализация, hook и runner.
- Подтверждения запусков: успешный и ошибочный вызовы MCP tool, запуск skill.
- Тесты и скрипт проверки: scripts/check.sh, tests/*.
- reflection.md с наблюдениями.

10. Подключение MCP (OpenCode 2.0.20)
- Конфигурация локального stdio-сервера в opencode.json:
  - mcp.servers.search_course_materials.type = "local"
  - mcp.servers.search_course_materials.command = [".venv/bin/python", "practices/practice_04/mcp/search_course_materials/mcp_server.py"]
  - cwd = "."; environment = {}
- Сервер реализован на FastMCP (mcp.server.fastmcp.FastMCP);
  - Регистрация инструмента search_course_materials.search произведена через server.tool(...).
  - Валидация входа и обработка ошибок реализованы в теле обработчика (INVALID_INPUT, INVALID_INCLUDE).

Примечание: Детали реализации (например, механизм проверки ссылок/блоков кода или способ поиска по материалам курса) выбираются прагматично, с акцентом на воспроизводимость и ясность интерфейсов.
