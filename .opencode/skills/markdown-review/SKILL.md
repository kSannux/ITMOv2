# markdown-review

Назначение
- Автоматически проверять Markdown-файлы в репозитории на частые ошибки:
  - битые локальные ссылки (относительные пути к несуществующим файлам),
  - незакрытые блоки кода (несбалансированные три обратные кавычки ```),
  - недостающие обязательные разделы (заданные заголовки #, ## и т.д.).

Входные параметры
- target_paths (обязательный):
  - Строка-глоб (например, "docs/**/*.md") или список путей/глобов.
- required_sections (необязательный):
  - Список названий разделов, которые должны присутствовать (например, ["Introduction", "Usage"]).
- options (необязательный объект):
  - check_anchors: true/false — при true дополнительно пытаться проверять локальные якоря внутри файла (по умолчанию false).

Выходные данные
- issues: список объектов с описанием найденных проблем:
  - type: "broken_link" | "unclosed_code_block" | "missing_section"
  - file: путь к файлу
  - line (опционально): номер строки
  - message: краткое описание проблемы
- summary: агрегированные счётчики по типам ошибок

Алгоритм выполнения
1) Сбор целей: развернуть глобы из target_paths, отфильтровать существующие .md файлы.
2) Парсинг файлов: читать построчно для последующих проверок.
3) Проверка ссылок:
   - Ищем шаблоны `[текст](путь)` без схемы (http/https/mailto не проверяются).
   - Разрешаем относительный путь относительно директории файла.
   - Если файл по пути не существует — регистрируем issue типа broken_link.
4) Проверка блоков кода:
   - Подсчитать количество маркеров ```.
   - Если количество нечётное — регистрируем issue типа unclosed_code_block (линия последнего обнаруженного маркера).
5) Проверка обязательных разделов:
   - Для каждого required_sections искать заголовок вида ^#{1,6}\s+<section>.
   - При отсутствии — регистрировать issue типа missing_section.
6) Сводка: сформировать summary по типам ошибок и вернуть issues + summary.
7) Обработка ошибок ввода:
   - Если target_paths не задан — вернуть ошибку INVALID_INPUT с сообщением о необходимости указать пути.

Используемые инструменты
- MCP tool: search_course_materials (по необходимости)
  - Назначение: найти примеры разделов или стандарты оформления в материалах курса (lections/, practices/, docs/, README.md), чтобы формировать рекомендации.
  - Вызов: search(query, include?, limit?) → results {path, line, snippet}.

Политика ошибок
- INVALID_INPUT: отсутствует или пустой target_paths.
- Внутренние ошибки парсинга/ФС: возвращать сообщение с указанием файла и контекста.

Примеры
- Успешная проверка (без ошибок):
  - Вход: { target_paths: "docs/**/*.md", required_sections: ["Introduction"] }
  - Выход: { issues: [], summary: { broken_link: 0, unclosed_code_block: 0, missing_section: 0 } }
- Ошибка ввода:
  - Вход: { }
  - Выход: ошибка INVALID_INPUT с сообщением о target_paths

Заметки по реализации
- Проверка ссылок не охватывает внешние URL.
- Для простоты считаем только тройные маркеры ``` без вариаций (например, ~~~ не учитываются).
- Секции сравниваются регистрозависимо; при необходимости можно добавить нормализацию регистра.
