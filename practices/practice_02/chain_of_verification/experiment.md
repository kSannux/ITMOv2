# Chain of Verification

Файл ведёт OpenCode по вашим запросам. Агент записывает фактические результаты экспериментов и вносит изменения в связанные файлы. Свою оценку сообщайте ему в чате; вручную заполнять шаблон не нужно.

- Проверяемый черновик или утверждение:

TO BE → Выход и правила (analysis.md):
- JSON-ответ с верхнеуровневым полем comment, где:
  - summary — строка;
  - risks — массив ≤3 элементов; каждый risk: file (путь из +++), line (N или N–M, 1-базовая, по стороне «+»), evidence (дословная цитата из diff);
  - checks — массив объектов {action, expected}, строки непустые;
- Успех: 200 OK, Content-Type: application/json; нарушение валидации diff — 422;
- Нормализация: ровно один top-level ключ comment; гарантированы summary/risks/checks; обрезка risks до 3.

## Запрос на проверку


Проверь, что указанные требования согласованы с context.md, product_management.md и tests_* и формулируются проверяемо. Для каждого спорного пункта верни вопрос, источник/проверку и результат.

## Исправленный результат


Оставляем TO BE → Выход и правила в части, подтверждённой источниками. Уточнения без источника отклонены.

- JSON {comment: { summary: string; risks≤3 (file, line, evidence — цитата из diff); checks: список шагов и ожидаемых результатов }}
- Ошибка валидации diff — 422; успешный ответ и Content-Type не уточняем
- Нормализация и формат line/file/checks как {action, expected} — в analysis.md не закрепляем (зафиксированы как предложения RCTF)

## Что изменили в исходном артефакте

- Файл и раздел: practices/practice_01/analysis.md — раздел TO BE
- Изменение: оставили только подтверждённые источниками части (comment{summary, risks≤3(file/line/evidence), checks}; 422 при невалидном diff); убрали неподтверждённые уточнения
- Что отклонили: Content-Type application/json; «один top-level key comment»; точный формат line/file; структура checks {action, expected}

Скрытые рассуждения модели не сохраняйте; нужны только вопросы, подтверждения и исправленный результат.
