## Context Pack для первого рабочего сценария

### Факты и правила

- Вход — один diff PR (`TRAINING_PR.diff`).
- Помощник возвращает: 1) краткое описание изменения; 2) до трёх рисков с файлом и строкой; 3) список воспроизводимых проверок.
- Выводы должны подтверждаться фрагментом diff или явным источником.
- Решение всегда принимает человек.

### Формат входа и результата

- Вход: текстовый diff в формате unified diff.
- Результат по умолчанию: список из 3 пунктов — описание, до 3 рисков (file:line, обоснование), и проверки для запуска.

### Ограничения и запрещённые действия

- AI не может approve/merge/менять код.
- Запрещены предположения без ссылки на diff/источник.
- Не придумывать несуществующие файлы/строки/проверки.

### Хороший пример


app/api.py, create_review — обращение payload["diff"] вызывает KeyError,
если в теле запроса нет поля diff. Проверка: отправить POST /api/reviews
с пустым JSON-объектом и проверить ответ сервиса.

### Плохой пример


Код можно улучшить. Добавьте тесты и обработку ошибок.

### Что пока неизвестно

- Какой набор проверок и окружение доступны для запуска локально/в CI.
- Как фиксировать и хранить результаты проверок (инструменты, формат).
- Политика команд по количеству и формату комментариев в ревью.

## Как использовали AI

 - Для чего: собрать и зафиксировать контекст (AS IS) и Context Pack: факты, формат, ограничения, примеры.
- Тип промпта: zero-shot (P1-01), master prompt (P1-02)
- Строка в [`prompts.md`](prompts.md): P1-01, P1-02, P1-03
- Что проверил студент и какие исправления поручил агенту: подтверждён пример хорошего комментария (KeyError в app/api.py). Уточнили границы (без approve/merge/изменений) и формат результата; зафиксированы неизвестные (версия Python, синхронность клиента LLM) как открытые вопросы.
