# Спецификация логики: Экспорт видимых данных в JSON

Короткое имя фичи: export-json

## 1. Цель и контекст

Фича предоставляет возможность экспортировать «видимые» (уже отфильтрованные и сформированные в UI) данные в JSON. Логическая функция принимает массив отфильтрованных элементов и словарь примененных фильтров, формирует валидный JSON-объект заданной структуры и возвращает его содержимое. Запись в файл и взаимодействие с UI лежат вне данного контракта.

## 2. Контракт входных и выходных данных

- Вход:
  - filtered_items: список элементов данных, каждый элемент — JSON-сериализуемый объект (см. раздел «Структуры данных»).
  - filters_applied: словарь примененных фильтров (ключи — строки; значения — JSON-сериализуемые примитивы или вложенные структуры).

- Выход:
  - Строка с содержимым JSON (UTF-8), соответствующая формату:
    {
      "export_date": "ISO-8601 string (UTC)",
      "total_items": int,
      "filters_applied": dict,
      "data": [ ... ]
    }

- Ошибки:
  - При пустом списке filtered_items выбрасывается ValueError("Empty dataset").

Примечание: запись на диск/в файл обрабатывается вызывающей стороной.

## 3. Структуры данных

- SerializableItem: ассоциативный объект (словарь), где:
  - ключ: строка (имя поля);
  - значение: JSON-сериализуемое значение одного из типов: string, number, boolean, null, массив перечисленных типов, объект-словарь с такими же ограничениями.

- ExportPayload (логическая модель итогового JSON):
  - export_date: строка в формате ISO 8601 (UTC), например: 2026-10-29T12:34:56Z;
  - total_items: целое число — количество элементов в data;
  - filters_applied: словарь примененных фильтров (как есть, без модификаций);
  - data: список SerializableItem.

Инварианты:
- export_date всегда проставляется текущей датой/временем в UTC и сериализуется в ISO 8601 с суффиксом Z;
- total_items == len(data);
- filters_applied не изменяется по пути формирования (копируется по значению);
- data содержит только JSON-сериализуемые значения; несериализуемые значения должны быть нормализованы (см. «Нормализация значений»).

## 4. Нормализация значений

Для обеспечения сериализации без потерь структуры допускаются следующие преобразования входных значений (если такие встречаются):
- datetime/date/time → ISO 8601 строка (UTC для datetime, без часового пояса — по умолчанию как локальное представление или [допущение: UTC]);
- Decimal → строка (чтобы избежать двусмысленности округления);
- Enum → значение-представление (строка или число);
- bytes/bytearray → base64-строка;
- Объекты с методом «asdict»/«to_dict»-подобным контрактом → словарь того же вида, далее рекурсивная проверка;
- Иные несериализуемые типы → строковое представление (последний безопасный вариант), при этом фиксируется факт деградации в логах/метаданных вызывающей стороны.

Если нормализация невозможна или нежелательна для домена, рекомендуется поднимать исключение на уровне вызывающего кода до передачи в функцию экспорта. Данная функция гарантированно поднимает исключение только при пустом наборе данных (см. «Ошибки»).

## 5. Алгоритм

1. Валидация входов:
   - Проверить, что filtered_items — коллекция; если пустая — выбросить ValueError("Empty dataset").
   - Если filters_applied == None — заменить на пустой словарь {}.

2. Нормализация данных:
   - Пройти по каждому элементу filtered_items:
     - Убедиться, что элемент может быть сериализован в JSON; при необходимости применить правила «Нормализация значений» для каждого поля.
     - Сформировать нормализованный элемент (deep copy с заменой полей).

3. Формирование полезной нагрузки ExportPayload:
   - export_date ← текущий момент в UTC, ISO 8601 (суффикс Z);
   - total_items ← количество элементов после нормализации;
   - filters_applied ← копия входного словаря;
   - data ← список нормализованных элементов в исходном порядке.

4. Сериализация:
   - Сформировать строку JSON на основе ExportPayload.
   - Гарантировать корректное кодирование Unicode (без экранирования символов) и детерминированность типов.

5. Возврат результата:
   - Вернуть полученную строку JSON. Запись на диск выполняет вызывающая сторона.

## 6. Обработка ошибок

- Пустой набор данных: выбрасывается ValueError("Empty dataset").
- Прочие ошибки сериализации/нормализации: допускается пробрасывать исключения наверх (решение обрабатывается на уровне интеграции), при этом функция не должна молча «съедать» ошибки.

## 7. Краевые случаи и устойчивость

- Очень большие значения чисел: Decimal переводится в строковое представление для избежания потери точности;
- Длинные строки и Unicode: JSON должен сохранять Unicode без потерь;
- Глубоко вложенные структуры: допускается глубина по умолчанию JSON; при превышении — ошибка сериализации пробрасывается наверх;
- Порядок полей в объектах: не гарантируется; потребители не должны полагаться на порядок ключей;
- Значения NaN/Infinity: приводятся к строкам "NaN"/"Infinity" или исключение (допущение см. ниже).

## 8. Функциональные требования (FR)

- FR1: Функция принимает список элементов и словарь фильтров. Неверные типы входов отклоняются или нормализуются (filters_applied=None → {}).
- FR2: При пустом списке элементов выбрасывается ValueError("Empty dataset").
- FR3: Поле export_date всегда задаётся в формате ISO 8601 (UTC, суффикс Z) на момент формирования.
- FR4: Поле total_items равно количеству элементов data.
- FR5: Поле filters_applied соответствует входному словарю (логическая копия без модификаций содержания).
- FR6: Поле data содержит нормализованные JSON-сериализуемые элементы, соответствующие входным по содержанию.
- FR7: Результат — корректный JSON, валидируемый по схеме ExportPayload.
- FR8: Unicode-символы в значениях сохраняются в результирующем JSON.

## 9. Сценарии использования и тестирование

- Сценарий A (успешный):
  - Дано: filtered_items с ≥1 элементом; filters_applied — словарь.
  - Когда: вызывается функция экспорта.
  - Тогда: возвращается строка JSON; export_date — ISO 8601 (UTC); total_items == len(filtered_items); filters_applied совпадает; data соответствует нормализованным входам.

- Сценарий B (ошибка пустого набора):
  - Дано: filtered_items = [].
  - Когда: вызывается функция экспорта.
  - Тогда: выбрасывается ValueError("Empty dataset").

- Сценарий C (нормализация сложных типов):
  - Дано: элементы содержат datetime/Decimal/Enum/bytes.
  - Тогда: значения нормализуются по правилам; JSON — валиден; при невозможности — исключение пробрасывается наверх.

- Сценарий D (Unicode):
  - Дано: значения с кириллицей/эмодзи.
  - Тогда: символы сохраняются без потерь в JSON.

## 10. Критерии успеха

- CS1: 100% экспортов возвращают JSON, соответствующий структуре ExportPayload.
- CS2: 100% попыток экспорта пустого списка завершаются исключением ValueError("Empty dataset").
- CS3: В 95% случаев при объёме до 10 000 элементов время формирования JSON — ≤ 2 секунд.
- CS4: В 99% случаев Unicode-символы корректно воспроизводятся потребителем без искажений.

## 11. Допущения и ограничения

- Допущение 1: Входные элементы уже отражают «видимые» столбцы/поля; скрытые/служебные поля на вход не передаются.
- Допущение 2: Временные значения нормализуются к UTC; если исходная таймзона неизвестна, принимается UTC.
- Допущение 3: Значения NaN/Infinity/−Infinity сериализуются как строки "NaN"/"Infinity"/"-Infinity" для предсказуемости, если доменные правила не предписывают иного.
- Ограничение: Функция не выполняет фильтрацию, пагинацию, выборку столбцов или запись на диск — только формирование JSON содержимого по заданной структуре.

## 12. За рамками (out of scope)

- Механика построения фильтров и выборки данных;
- UI/UX компонентов, триггеры действий и загрузка файлов;
- Хранение и доставка файлов.
