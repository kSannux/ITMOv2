# Quickstart: проверка JSON-экспорта

Это руководство для проверки реализации по [плану](plan.md).

## Предусловия и окружение

Python 3.11+ и pytest. Все команды ниже запускать из каталога `practices/practice_05`. Исходники и тесты находятся в `export_json.py` и `tests/test_export_json.py`.

```sh
python3 -m pytest -q tests/test_export_json.py
```

Ожидается отсутствие ошибок и покрытие случаев из [контракта](contracts/python-export.md). Экспорт использует только стандартную библиотеку.

## Ручная сквозная проверка библиотеки

```sh
python3 -c 'import json; from export_json import export_visible_to_json; print(json.dumps(json.loads(export_visible_to_json([{"id": 2, "name": "Иван 🌍", "value": float("inf"), "note": None}], {"q": "Иван"})), ensure_ascii=False, indent=2))'
python3 -c 'from datetime import datetime, timezone; from export_json import make_export_filename; print(make_export_filename(datetime(2026, 10, 29, 12, 34, 56, tzinfo=timezone.utc)))'
```

Ожидается объект с total_items=1, неизменными фильтрами, value="Infinity", note=null, читаемым Unicode и export_date UTC Z; имя `export-20261029-123456.json`. Это проверка от Python-вызова до разбираемого содержимого файла; загрузка в браузере проверяется отдельно.

## Матрица pytest

| Сценарий | Проверка |
| --- | --- |
| Текущая страница | Передать две строки из выбранной страницы; получить только их и видимые поля в том же порядке |
| Пустой набор | Точное ValueError("Empty dataset") |
| Фильтры | None → {}; вложенный словарь равен исходному; входы неизменны; невалидные значения отклонены |
| Специальные числа | Все три значения на разных глубинах становятся строками; strict JSON parse не обнаруживает нестандартных токенов |
| Нормализация | Decimal, Enum, bytes, даты/время соответствуют контракту; микросекунды datetime сохранены |
| Ошибки | Неподдержанные объекты/ключи/циклы не возвращают частичный документ и не меняют вход |
| Время и имя | UTC независимо от локального пояса; перевод timezone корректен |

Модель и инварианты: [data-model.md](data-model.md).

## Производительность

Запустить измерительный сценарий:

```sh
python3 scripts/benchmark_export_json.py
```

Сценарий выполняет один прогрев и 20 измерений по 10 000 строк (id, кириллический name, bool, вложенный список трёх чисел), используя perf_counter. Не менее 19 измерений должны укладываться в 2 с; вывод содержит все длительности, p95 по nearest-rank, размер входа и среду. Нарушение порога даёт ненулевой exit code. Это проверяет SC-4 на фиксированном наборе, а не произвольные гигантские строки.

## UI-интеграция

На экране с несколькими страницами проверить экспорт только активной страницы, видимые поля, сохранение порядка, имя UTC и фактический старт скачивания. Для пустой страницы кнопка native disabled; tooltip «Нет данных для экспорта» доступен с клавиатуры через обёртку и читается скринридером, тоста нет. Для длительной операции Loading блокирует повтор; после успеха или ошибки состояние пересчитывается. При искусственной ошибке сериализации показывается общий тост, файл не выдаётся. При Empty dataset после запуска тоста «нет данных» нет. Для SC-1 измерить 20 запусков на ≤5 000 строках: минимум 19 стартов скачивания за ≤5 с.
