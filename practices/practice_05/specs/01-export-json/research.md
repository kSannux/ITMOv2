# Research: export-filtered-json

## Контекст и источники решений

Использованы спецификация, уточнения пользователя, существующие `export_json.py` и `tests/test_export_json.py`, инструкции репозитория и отдельное исследование агента по Python stdlib/pytest. Веб-исследование для этих стабильных API не требовалось. Все решения Phase 0 определены ниже.

## 1. Размещение и граница ответственности

- **Decision**: доработать корневой `export_json.py`; экспорт принимает готовую текущую страницу и видимые поля, возвращает строку. UI управляет выборкой и скачиванием. Предоставить отдельную функцию UTC-имени файла.
- **Rationale**: модуль и pytest-файл уже существуют; это исключает конкурирующие реализации. Совпадает с распределением ответственности в спецификации.
- **Alternatives considered**: новый модуль внутри practice_05, HTTP-сервис, CLI и собственная таблица — дублирование или расширение области задачи.

## 2. Строгий JSON и Unicode

- **Decision**: рекурсивная нормализация данных до `json.dumps(..., ensure_ascii=False, allow_nan=False)`. None/bool/int/str/конечные float сохраняют значения; NaN/Infinity/-Infinity становятся точными строками. Ключи словарей только строки, без неявного str(key).
- **Rationale**: default-обработчик json не перехватывает встроенные нечисловые float; allow_nan=False предотвращает невалидный JSON. Преобразование ключей может создать коллизии `1` и `"1"`.
- **Alternatives considered**: стандартный вывод NaN, постобработка текста JSON, stringify любых объектов — невалидный JSON или потеря данных.

## 3. Копирование фильтров и снимок

- **Decision**: filters_applied=None означает {}; иначе только словарь с JSON-совместимыми вложенными значениями и строковыми ключами. Глубокая копия без изменения значений. Нефинитные числа и специальные типы в фильтрах отклоняются: вызывающий слой должен заранее передать JSON-совместимый словарь. Нормализация NaN/Infinity применяется к data; в фильтрах их строковая форма должна быть сформирована до вызова.
- **Rationale**: так одновременно сохраняются строгий JSON и требование «копия словаря без модификаций». Автоматическая нормализация фильтров нарушила бы последнее. Обычные строки "NaN" в фильтрах допустимы.
- **Alternatives considered**: поверхностная копия, изменение фильтров при нормализации, вывод невалидных токенов — отвергнуты. Это ограничение входа, которое должно быть отражено при синхронизации spec.md.

UI фиксирует страницу, поля, строки, фильтры и порядок при запуске. Библиотека не мутирует входы и создаёт отдельное дерево результата; вызывающий код не изменяет входные структуры одновременно с вызовом. Глубокая копия сама по себе не обеспечивает атомарный снимок при конкурентной записи.

## 4. Нормализация специальных типов

- **Decision**: datetime → ISO 8601 UTC Z с сохранением микросекунд; наивный datetime трактуется как UTC. date → ISO-дата. time с фиксированным смещением → время UTC (опорная дата 2000-01-01, день отбрасывается); наивное time → время UTC; суффикс Z. Объекты time с timezone, не задающей смещение без даты, отклоняются. Decimal → строка, включая стандартные нечисловые значения; Enum → рекурсивно нормализованное строковое/числовое value; bytes/bytearray → base64 ASCII. Списки и словари обходятся рекурсивно.
- **Rationale**: UTC предсказуем независимо от локальной TZ; дробные секунды нельзя терять. У time нет даты для вычисления сезонного смещения.
- **Alternatives considered**: обрезка микросекунд, локальная TZ, предположение даты для сезонной зоны, Decimal → float — потери или неоднозначность.

Неподдержанные объекты/tuple/set, нестроковые ключи и неподходящий Enum отклоняются TypeError. Автоматический вызов произвольных to_dict/asdict и fallback str не входят в минимальный публичный контракт. Циклы отклоняются ValueError; общий объект в разных ветвях без цикла допустим. Превышение допустимой глубины может дать RecursionError; частичный JSON не возвращается.

## 5. Время, имя файла и ошибки

- **Decision**: export_date определяется через datetime.now(timezone.utc); имя по UTC export-YYYYMMDD-HHMMSS.json. Вспомогательная функция принимает необязательный datetime для повторяемых тестов; наивное значение считается UTC. Коллизии имён в одну секунду допустимы, разрешение выполняет механизм сохранения UI.
- **Rationale**: сохраняется согласованный шаблон; глобальный счётчик имён не требуется. Пустой список всегда ValueError("Empty dataset"); неправильный тип входа — TypeError, а не «пусто».
- **Alternatives considered**: локальное время и случайный суффикс — меняют согласованный формат.

## 6. Тестирование и производительность

- **Decision**: pytest с проверкой разобранного документа и неизменности входов; точное сопоставление ошибок; строгий разбор JSON с отклонением нестандартных токенов; отдельный benchmark SC-4 на 10 000 строках, 20 измерений после одного прогрева, ≥19 результатов ≤2 с.
- **Rationale**: тесты проверяют контракт, а не внутреннюю структуру кода. Нестабильный тайминг не должен делать обычные unit-тесты случайными.
- **Alternatives considered**: проверки только наличия ключей и единичный замер — недостаточны для целостности и 95-процентного критерия.

Benchmark использует строки с id, кириллическим name, bool и вложенным списком из трёх чисел; фиксирует Python/ОС/оборудование и длительности. Это воспроизводимая базовая нагрузка, не доказательство для произвольных размеров полей. SC-1 измеряется отдельно при UI-интеграции от клика до старта скачивания.
