### Метод воспроизведения E09 и E10

В чате предложена однократная подмена `app.export_visible_to_json` в памяти
тестового Flask-процесса. Файлы приложения не требуется менять.
Для E09 первый вызов выбрасывает RuntimeError; для E10 — точное
ValueError("Empty dataset"). Последующие вызовы используют оригинальную функцию.
Пользователь подтвердил прохождение сценариев; скриншоты фиксируют HTTP 500/409.
Терминальный лог подмены отдельно не приложен.

Остановить штатный сервер и выполнить из каталога практики:

```sh
CASE=E09 .venv/bin/python - <<'PY'
import os
import app as web

original = web.export_visible_to_json
scenario = os.environ['CASE']
first_call = True

def simulated_export(*args, **kwargs):
    global first_call
    if first_call:
        first_call = False
        if scenario == 'E09':
            raise RuntimeError('E09: simulated serializer failure')
        if scenario == 'E10':
            raise ValueError('Empty dataset')
    return original(*args, **kwargs)

web.export_visible_to_json = simulated_export
web.app.run(host='127.0.0.1', port=5000, debug=False, use_reloader=False)
PY
```

Для E10 заменить `CASE=E09` на `CASE=E10` и перезапустить процесс.
Первый экспорт при непустой таблице должен дать соответственно
500 `{"error":"export_failed"}` или 409 `{"error":"empty_dataset"}`.
Второй — HTTP 200 и файл. E10 моделирует защитную ветку, не реальную гонку.
После проверки остановить процесс и вернуть обычный `.venv/bin/python app.py`;
сеть вернуть в No throttling.
